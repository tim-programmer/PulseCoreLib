# Math (`pcl_math.h`)

Files: `include/pcl/pcl_math.h`, `src/core/pcl_math.c`, two new constant tables in
`src/core/pcl_tables.c` (generated by `tools/gen_tables.c`), `src/core/pcl_octave.h` (shared 2^x
helpers, see decision 6), `tests/test_math.c`, the `math_*` cases of `platform/bench/pcl_bench.c`.
`include/pcl/pcl_types.h` gained `pcl_db_t`, `pcl_wide_t` and their constants.

**Status: implemented in float, Q15 and Q31; all tests pass in all three builds** (Clang with
ASan + UBSan, GCC `-O2`, and the `cm0plus-*` / `cm33-*` compile checks including the no-soft-float
check). Accuracy, code size and the **Cortex-M33 cycle counts are measured** (FRDM-MCXN947, bit-exact
against the host build in all three types). **Cortex-M0+ is unmeasured**: there is no hardware.

## Summary

The shared conversions and shapes that the filters, the event modules and the effects will need,
as one public header. Nothing here has state: every function is pure.

```
pitch   pcl_hz_scale(f, oct)      f * 2^oct                       (public face of src/core/pcl_octave.h)
        pcl_hz_to_oct(f, ref)     log2(f / ref)                   (inverse; new log2 table)
        pcl_midi_to_hz(note)      440 * 2^((note-69)/12)
        pcl_cents_to_oct(cents)   cents / 1200
level   pcl_db_to_gain(db)        10^(db/20)  -> pcl_coef_t
        pcl_gain_to_db(gain)      20*log10(gain)
shapes  pcl_sin(phase), pcl_cos(phase)    uint32 phase, 2^32 = one cycle
        pcl_tan_hz(f, fs)         tan(pi f / fs): the cutoff pre-warp of every TPT/bilinear filter
        pcl_tanh(x)               saturator, audio rate, x may exceed full scale
helpers pcl_sample_to_wide / pcl_wide_to_sample
```

* **Fixed-point builds use no float, anywhere** (the setters included, so a no-FPU filter can retune
  its cutoff from a control loop without the float runtime).
* **Same table-based algorithms in all three builds** (as the oscillator and LFO do), so the three
  types agree to within their own resolution. No `expf`, `tanhf`, `tanf`, `log2f`.
* Everything is **pure and reentrant**: no state, no allocation.
* None of them can fail, so none returns `pcl_status_t`; an out-of-range argument is clamped as the
  domain table says.

## Decisions taken

The draft's recommendations were all accepted. What changed while building them:

1. **Two new types in `pcl_types.h`** (`pcl_db_t`: float / Q8.24; `pcl_wide_t`: float / Q4.28; with
   `PCL_DB(x)`, `PCL_WIDE(x)`, `PCL_Q24_SHIFT`, `PCL_CONST_Q24`). Additive; no existing signature
   changed. **The draft said `PCL_DB_MIN` = -144 dB, which Q8.24 (+-128 dB) cannot hold; it is
   -120 dB** (a gain of 1e-6, 1070 LSB of Q2.30). `PCL_DB_MAX` = +6 dB.
2. **Tables in the float build too.** `pcl_tanh` is within 2.3e-5 of libm, below Q15's own LSB.
3. **A log2 table (257 x `uint16_t`, 514 B)** for `pcl_hz_to_oct` and `pcl_gain_to_db`.
4. **`tan` is computed two ways, which is not what the draft proposed.** The draft's prototype used
   the *Q31* sine table and measured sin/cos well; in a **Q15 build the shared sine table has only 15
   bits**, which at small arguments gives percent-level error (a 100 Hz cutoff would be 4 cents off).
   So below x = pi f / fs = 0.5 (f below 0.159 fs: 7.6 kHz at 48 kHz) the tangent is its **power
   series through x^11**, evaluated in Q4.28 (or float); above that it is sin / cos from the shared
   table with one division. The series is off by 9e-7 relative at x = 0.5, the same as the table path,
   is more accurate than the Q15 table everywhere below, and is cheaper than sin + cos + a division.
   Mutation testing showed an earlier limit of 0.25 left the last series terms untested (see below),
   which is why the limit is 0.5.
5. **`pcl_tanh` table [0, 6), 384 segments**, input `pcl_wide_t`, hold at the last entry beyond.
6. **Public wrappers, with one small extraction.** `pcl_hz_scale` and `pcl_sin` wrap existing internal
   code. To share the 2^x fraction with `pcl_db_to_gain`, the table-interpolation lines of
   `pcl_octave_scale_inc` / `pcl_octave_scale_f` moved into `pcl_exp2m1_q16` / `pcl_exp2_frac_f`
   (same arithmetic, same order). **The output of the 25 oscillator, noise, S&H, VCA and LFO benchmark
   cases is byte-identical before and after, in all three types** (checked against the saved golden
   files; only the "cases=N" digits of the banner differ).
7. **Out of line** (`pcl_math.c`) for everything that touches a table; `pcl_sample_to_wide` and
   `pcl_wide_to_sample` are `PCL_INLINE` in the header (no table, a few instructions).

## API

```c
/* ---- pitch ---- */
pcl_hz_t  pcl_hz_scale(pcl_hz_t f, pcl_oct_t oct);       /* f * 2^oct */
pcl_oct_t pcl_hz_to_oct(pcl_hz_t f, pcl_hz_t ref);       /* log2(f / ref) */
pcl_hz_t  pcl_midi_to_hz(uint8_t note);                  /* 0 .. 127 */
pcl_oct_t pcl_cents_to_oct(int32_t cents);               /* cents / 1200 */
/* ---- level ---- */
pcl_coef_t pcl_db_to_gain(pcl_db_t db);
pcl_db_t   pcl_gain_to_db(pcl_coef_t gain);
/* ---- shapes ---- */
pcl_sample_t pcl_sin(uint32_t phase);
pcl_sample_t pcl_cos(uint32_t phase);
pcl_wide_t   pcl_tan_hz(pcl_hz_t f, uint32_t sample_rate_hz);
pcl_sample_t pcl_tanh(pcl_wide_t x);
/* ---- sample <-> wide (identity in float builds) ---- */
pcl_wide_t   pcl_sample_to_wide(pcl_sample_t x);
pcl_sample_t pcl_wide_to_sample(pcl_wide_t x);           /* saturating */
```

| Function | Domain | Out of range |
|----------|--------|--------------|
| `pcl_hz_scale` | `oct` in [-8, 8) | `oct` clamped (NaN too, in float); fixed-point result saturates at 65535.99998 Hz |
| `pcl_hz_to_oct` | `f`, `ref` > 0 | `f == 0` gives -8, `ref == 0` (with `f > 0`) the largest octave, both zero 0; result clamped to [-8, 8) |
| `pcl_midi_to_hz` | 0 .. 127 | larger notes count as 127 |
| `pcl_cents_to_oct` | +-9599 cents | clamped just inside +-8 octaves |
| `pcl_db_to_gain` | `PCL_DB_MIN` .. 6.0206 dB | below -120 dB (or NaN): exactly 0; at 6.0206 dB (gain 2.0, which Q2.30 cannot hold) and above: 1.9999999, **in every build** (float included, so the three agree) |
| `pcl_gain_to_db` | gain > 0 | gain <= 0, NaN, or below -120 dB: `PCL_DB_MIN` |
| `pcl_sin` / `pcl_cos` | any phase | none; full scale = the largest sample value |
| `pcl_tan_hz` | `f` up to 0.45 `fs` | `f` above that is clamped (tan is 6.31 there; Q4.28 tops out at 8; the pole is at 0.5); `fs` = 0 returns 0; NaN or negative `f` returns 0 (float) |
| `pcl_tanh` | any | beyond +-6 holds at +-0.99999; NaN gives 0 |

## Algorithms and accuracy (measured)

All figures are the worst case over dense sweeps of the whole domain in the final code, against a
`double` model evaluated at the quantised input (`tests/test_math.c` enforces them).

| Function | Float | Q15 | Q31 | Notes |
|----------|------:|----:|----:|-------|
| `pcl_hz_scale` | 6.8e-6 rel | 1.5e-5 rel | 1.5e-5 rel | fixed: two 16-bit roundings (table entry, interpolated mantissa); 0.026 cents; plus 1 LSB of Q16.16 |
| `pcl_hz_to_oct` | 1.5e-5 oct | 2.0e-5 oct | 2.0e-5 oct | 0.025 cents; fixed subtracts two log2 lookups; float's last table segment contributes the 1.5e-5 (the saturated 65535 entry) |
| `pcl_midi_to_hz` | 4.5e-6 rel | 4.9e-6 rel | 4.9e-6 rel | note 69 is exactly 440 Hz; octaves are exact in the exponent |
| `pcl_cents_to_oct` | 4e-7 | 2e-9 | 2e-9 | 1200 cents is exactly 1.0 |
| `pcl_db_to_gain` | 7.9e-6 rel | 1.5e-5 rel | 1.5e-5 rel | 0.00013 dB; fixed also rounds to a Q2.30 LSB (visible only below -90 dB) |
| `pcl_gain_to_db` | 8.3e-5 dB | 1.1e-4 dB | 1.1e-4 dB | |
| `pcl_sin` / `pcl_cos` | 4.8e-6 | 6.2e-5 (2 LSB) | 4.8e-6 | the shared table; Q31's 32-bit interpolation loses up to ~1e-7 more at segment tops |
| `pcl_tan_hz`, x < 0.5 | 2e-7 rel | 1.3e-5 rel below 48 Hz, 1.7e-6 to 480 Hz, 2e-7 above | same | fixed: Q4.28 quantisation (3.7e-9 absolute) dominates only at the lowest cutoffs (48 kHz figures) |
| `pcl_tan_hz`, x >= 0.5 | 9e-7 rel | 1.2e-4 rel (0.21 cents) | 1.0e-6 rel | Q15: its sine table |
| `pcl_tanh` | 2.4e-5 abs | 6.9e-5 (2.3 LSB) | 2.4e-5 abs | table error 2.3e-5; Q15 adds output rounding |

So: pitch conversions are within 0.03 cents, cutoff pre-warping within 0.25 cents over the whole audio
range in every build (0.003 cents in Q31/float above 48 Hz), levels within 0.0002 dB.

**One property to know about, Q15 only:** `pcl_tan_hz` steps *backwards* once, by 2.9e-5 relative
(0.05 cents), where the power series hands over to the 15-bit sine table at x = 0.5 (the table sits a
hair below the series there). Everywhere else it is monotone, and in Q31 and float it is monotone
across the junction too. A filter that sweeps its cutoff through 7.6 kHz (at 48 kHz) in Q15 sees a
0.05-cent glitch in the coefficient; the test pins it so it cannot grow.

### Pitch and level: one exp2, one log2

`2^x` is the table already shipped for the oscillator and LFO (`pcl_exp2_tab`, 256 segments, linear
interpolation, 514 B). `pcl_midi_to_hz` splits `note - 69` into whole octaves and a remainder of 0..11
semitones, so every octave of A is exact and only the fractional part uses the table.
`pcl_db_to_gain` computes `2^(db * log2(10)/20)`; the integer part of the exponent becomes a right
shift of the Q2.30 result (down to 2^-20), so gains far below the octave scaler's 2^-8 still work.

`pcl_hz_to_oct` and `pcl_gain_to_db` use a **log2 table**: `round(log2(1 + i/256) * 65536)` for i =
0..256 as `uint16_t` (the last entry saturates 65536 to 65535, like the exp2 table). The integer part
is the position of the top set bit (a fixed five-step search, no compiler intrinsic); the float build
reads it from the exponent field of the IEEE value (`memcpy`; a static assertion checks that `float`
is 32 bit).

### `pcl_tan_hz`

`r = f / fs` is formed as a phase increment (`f * 2^16 / fs`, one 64/32 division) and `x = pi r` in
Q4.28. Below x = 0.5, `tan x = x + x^3/3 + 2x^5/15 + 17x^7/315 + 62x^9/2835 + 1382x^11/155925` by
Horner's rule in x^2; above, `sin(pi r) / cos(pi r)` from the quarter-wave table (the angle pi r is
the phase `inc / 2`, below a quarter cycle, so both are positive and cos >= 0.156) with one more
division. The sin / cos branch widens Q15 samples to Q31 first.

### `pcl_tanh`

A 384-segment table of `tanh(x)` on [0, 6], step 1/64, linear interpolation, symmetric about 0. The
input is a Q4.28 `pcl_wide_t`, so the table index is `|x| >> 22` and the interpolation fraction the
next 16 bits: no division. Entries are in the sample format. The alternatives rejected on
measurement: the clamped rational `x(27+x^2)/(27+9x^2)` is off by 2.4e-2 and `x/(1+|x|)` by 0.31.
The output is odd-symmetric exactly, monotone, and continuous at every table joint and at the hold.

### `pcl_tan_inc` (added with the state-variable filter)

`pcl_tan_inc(phase_increment)` is `pcl_tan_hz` with `f / fs` already formed as a phase increment
(2^32 = the sample rate), clamped at 0.45 * 2^32. `pcl_tan_hz` now forms the increment (one division)
and calls it. The fixed-point results are bit-identical (all 48 benchmark cases at the time were
byte-identical before and after; `test_tan_inc` checks equality with `pcl_tan_hz` and the clamp); in
float the increment is converted back to a ratio, within 2e-6 relative. A filter that holds its
cutoff as an increment avoids the division on every retune.

## Memory

* **State:** none.
* **Flash tables (measured, `pcl_tables.o`):** the library now carries 2312 B (Q15) / 3596 B (Q31,
  float) of constant tables: sine 514 / 1028 B, exp2 514 B (both from before), **log2 514 B and
  tanh 770 / 1540 B (new)**. A build that never calls the log or tanh functions can drop the new
  tables with `-ffunction-sections -fdata-sections -Wl,--gc-sections`.
* **Code (`pcl_math.o`, text, arm-none-eabi-gcc, the presets' default flags):** Cortex-M0+ Q15 2560 B,
  Cortex-M0+ Q31 2464 B, Cortex-M33 float 2450 B, Cortex-M33 Q31 2534 B (draft estimate: 1.5-2.5 KB).
  The M0+ objects reference only integer helpers: `__aeabi_lmul`, `__aeabi_uidiv(mod)`,
  `__aeabi_uldivmod`; no soft-float routine (the build's check enforces it).

## Rate

Stateless, so the rate is the caller's. `pcl_sin`, `pcl_cos`, `pcl_tanh` and the two conversions are
meant for the audio loop; the pitch, level and `pcl_tan_hz` functions for setters.

## Cost (cycles per call): MEASURED on a Cortex-M33

Measured on the **FRDM-MCXN947 (Cortex-M33 + FPU, 150 MHz)** with the DWT cycle counter, `-O2`,
from flash with the SDK's default flash cache on, 256-call blocks of seeded random arguments
(`math_*` cases of the bench). The figures below are **net of a `math_baseline` case** (a loop that
loads, folds and stores through a `volatile` pointer: 8.1 / 6.1 / 8.1 cycles in Q15 / Q31 / float),
so they are the call's own cost including argument conversion in the callee. Spread between blocks is
under 1.5 % (`pcl_tanh`: 11 %, data-dependent saturation).

| Function | Q15 | Q31 | float | Draft estimate (M33) |
|----------|----:|----:|------:|---------------------:|
| `pcl_sin` | 27 | 22 | 21 | 15-25 |
| `pcl_tanh` | 23 | 23 | 36 | 20-30 |
| `pcl_hz_scale` | 41 | 41 | 73 | 30-50 |
| `pcl_midi_to_hz` | 49 | 50 | 89 | 30-50 |
| `pcl_cents_to_oct` | 22 | 23 | 14 | 30-50 |
| `pcl_db_to_gain` | 47 | 48 | 72 | 40-60 |
| `pcl_hz_to_oct` | 125 | 125 | 76 | 60-100 |
| `pcl_gain_to_db` | 76 | 78 | 52 | 60-100 |
| `pcl_tan_hz`, x < 0.5 (series) | 191 | 192 | 70 | 100-150 |
| `pcl_tan_hz`, x >= 0.5 (sin / cos) | 281 | 283 | 98 | 100-150 |

* **The fixed-point `pcl_tan_hz` is dearer than estimated.** About 100+ cycles of it is the 64-bit
  division `f * 2^16 / fs` (`__aeabi_uldivmod`), and the sin / cos branch has a second. A filter that
  retunes every control period (every 16 samples) would pay roughly 12 cycles per sample on the M33,
  and substantially more on Cortex-M0+ (software divide), where I have not measured it. The way out,
  for the filter spec rather than this module, is a phase-increment form of the function that takes
  `f / fs` already computed (the oscillator and LFO already hold that), which removes the first
  division.
* **Float is faster than fixed for the logarithms, `tan` and `cents_to_oct`, and slower for the 2^x
  functions and `tanh`.** I did not investigate why; the M33's FPU does single-precision divide and
  multiply in a few cycles, which is the likely reason for the first group.
* **Cortex-M0+ is unmeasured.** The M33 numbers do not transfer: the M0+ has no 32x32->64 multiply or
  hardware divide, and the 64-bit arithmetic in the setter-rate functions becomes library calls.

### Two harness bugs found while measuring (both fixed)

1. The first Q15 run read about twice the Q31 cost for the *same compiled code*. The cause was my own
   `BENCH_FOLD` macro, which evaluated its argument twice (so every call ran twice in Q15 only).
   The outputs were still right, since the functions are pure; only the timing was wrong. It is now an
   inline function.
2. The first baseline (a plain copy loop, then a loop calling `pcl_wide_to_sample`) read 14-20
   cycles: GCC turned the copy into a call to the C library's `memcpy`, and the other loop measured the
   saturating function. The baseline now stores through a `volatile` pointer and reads 6-8.

These only affected the new `math_*` cases. The earlier modules' process functions write their own
output loops, which the compiler cannot turn into a `memcpy`; their numbers were not re-measured.

## Tests (`tests/test_math.c`, 22 groups, ~1.36 million checks)

Each function against an independent `double` model evaluated at the quantised input, with the
tolerances above:

* **Accuracy sweeps** over each full domain: `hz_scale` (octave x frequency grid), `hz_to_oct`,
  all 128 notes, every cents value in range, `db_to_gain` across -120 .. +6 dB, `gain_to_db` across
  1.2e-6 .. 1.99, 200,000 phases for sin / cos, `tan_hz` for sample rates 8, 44.1, 48, 96 and 768 kHz
  from 5 Hz to 0.45 fs, `tanh` over +-7.
* **Landmarks, exact:** `hz_scale(f, 0) == f`; note 69 = 440 Hz exactly; 1200 cents = 1.0; 0 dB =
  gain 1.0 exactly (`1 << 30`); `tanh(0) = 0`; `sin(0) = 0`; the tan clamp value.
* **Round trips:** `hz_scale(f, hz_to_oct(g, f))` returns `g`; `db_to_gain` / `gain_to_db`; `n + 12`
  is twice `n` for MIDI notes.
* **Monotonicity** of `hz_scale`, `db_to_gain`, `tan_hz` (two sample rates), `tanh`, and strict increase
  of `midi_to_hz`; plus a walk of every Q16.16 cutoff step across the `tan_hz` series / sin-cos
  junction at four sample rates (no backward step in Q31 and float, at most one of under 5e-5 in Q15).
* **Symmetry and structure:** `tanh` exactly odd; `sin(p + half) == -sin(p)`; `cos(p) == sin(p + quarter)`;
  `tanh` equals its table at every one of the 384 joints.
* **Clamps:** every row of the domain table, including `INT32_MIN`/`MAX` arguments and, in float,
  NaN and +-Inf; the 80 consecutive dB values around the 2.0 saturation boundary.
* **Sample <-> wide:** round trip, saturation at exactly +-1.0 and beyond, Q15 rounding of ties.
* `test_tables.c` gained the log2 and tanh tables (against libm, monotone) and `test_types.c` the new
  macros and limits.

### Mutation testing

34 deliberate bugs, one at a time, in scratch copies (flipped sign of the odd extension, off-by-one
table index, dropped rounding, changed clamps and constants, dropped series terms, removed guards,
swapped operands, shifted series limit):

* 30 are caught by the tests. Where a mutant made the process crash (a removed `fs == 0` guard, or a
  removed float dB floor indexing past a small table) the crash counts as detection.
* **The first run showed 13 survivors** (two of them were crashes my runner did not yet count). The
  real test gaps, now closed: the tan clamp between 0.45 and 0.46 fs; `pcl_wide_to_sample` at exactly +1.0 in Q31 (it would wrap to -1.0); Q15
  rounding of that function; and the tan series, whose last terms and 0.25 limit were *invisible at
  the test tolerance* because the series was more accurate than the check (hence the change to 0.5,
  where every term matters).
* **Four stay alive and are not defects:** `tanh`'s hold threshold `>=` to `>` reads one entry past the
  table with an identical value, so only a sanitizer sees it, and **ASan does** (global-buffer-overflow);
  `db_to_gain`'s saturation `>=` to `>` is equivalent because no Q8.24 input maps to exactly 2^28 (the
  mapping steps 2-3 at a time across it); a 1-unit change of the `gain_to_db` scale constant and
  the 0.5-LSB rounding of the sin / cos quotient are below the format resolution.
