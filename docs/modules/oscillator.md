# Oscillator (band-limited: sine, triangle, saw, square/pulse)

Header: `include/pcl/pcl_osc.h` - Source: `src/osc/pcl_osc.c` - Tables: `src/core/pcl_tables.c`
(generated by `tools/gen_tables.c`) - Example: `examples/sweep_wav.c`

**Status: implemented in float, Q15 and Q31; all tests pass in all three builds, and the
library produces identical output on a real Cortex-M33 (see "On hardware").** Sizes, accuracy,
aliasing and (Cortex-M33) cycle figures below are **measured**. Cortex-M0+ cycle counts were
never measured.

## Summary

One oscillator, four waveforms, three optional inputs:

```
out[n] = wave( phase[n] ; pulse_width[n] )     phase: uint32_t, 2^32 == one cycle
phase[n+1] = phase[n] + inc[n]                 inc = f(n) / sample_rate * 2^32
f(n) = f_base * 2^( pitch_mod * pitch_depth_oct )
```

* **Sine** from a quarter-wave table with linear interpolation (no discontinuities, so no
  correction needed).
* **Saw, square/pulse** corrected with 2-point **PolyBLEP** at each step discontinuity.
* **Triangle** corrected with 2-point **PolyBLAMP** at each slope discontinuity.
* **Pitch modulation** in octaves (1V/oct style), **PWM** input, **hard sync** in and out,
  with sub-sample-accurate reset and the same BLEP/BLAMP correction applied to the sync jump.
* **One sample of output latency** (see "Hard sync" for why). The first sample after
  `init`/`reset` is 0.

This is a "VC" module in the CLAUDE.md sense: one code path, a base frequency plus modulation
inputs. There is no separate VCO implementation.

## Decisions taken (the open questions in the first draft)

| Question | Decision |
|----------|----------|
| Modulation rate | Pitch and PWM are **control rate** (every `PCL_CONTROL_DIV` = 16 samples, linearly interpolated). No audio-rate FM. |
| Hz type | New `pcl_hz_t` in `pcl_types.h`: `float`, or unsigned **Q16.16** in Q15/Q31 builds. |
| Pulse DC | Raw +/-1 pulse; DC is `2*width - 1`. DC removal is left to a downstream high-pass. |
| Sine table | 257-entry quarter-wave table (514 B Q15, 1028 B otherwise). |
| Pitch depth | Per-oscillator `pitch_depth_oct`, a new `pcl_oct_t` (`float`, or signed **Q4.28**). |

## Parameters

| Parameter | Unit | Range | Notes |
|-----------|------|-------|-------|
| `sample_rate_hz` | Hz | 8000 .. 768000 | `uint32_t` |
| `waveform` | enum | `PCL_OSC_SINE`, `TRIANGLE`, `SAW`, `PULSE` | Setter; switching keeps the phase and may click |
| `frequency` | Hz (`pcl_hz_t`) | 0 .. 0.45 * sample_rate | Smoothed ~5 ms. 0 freezes the phase. Build with `PCL_HZ(x)` |
| `pitch_depth_oct` | octaves (`pcl_oct_t`) | 0 .. < 8 | Octaves per unit of `pitch_mod`. Build with `PCL_OCT(x)`. Not smoothed |
| `pulse_width` | fraction of a cycle (`pcl_coef_t`) | 0.01 .. 0.99 | Base width. Smoothed |
| `pwm_depth` | fraction of a cycle (`pcl_coef_t`) | 0 .. 0.49 | Width swing per unit of `pwm_mod`. Not smoothed |
| `pcl_osc_set_phase` | `uint32_t` | any | A deliberate jump; no correction applied |
| `pitch_mod` (input) | normalized | [-1, 1] | Optional. Octaves = `pitch_mod * pitch_depth_oct` |
| `pwm_mod` (input) | normalized | [-1, 1] | Optional; pulse only. Width = `pulse_width + pwm_depth * pwm_mod` |
| `sync_in` (input) | fraction of a sample | 0 or (0, 1] | Optional. See "Hard sync". Outside the range (a negative or NaN sample, or a float above 1) it is clamped: no event, and 1 |
| `sync_out` (output) | fraction of a sample | 0 or (0, 1) | Optional; `NULL` = not computed |

Output is nominally [-1, 1]. Fixed-point builds saturate; the float build does not clip.
Every buffer may alias any other. `init` and the setters range-check (NaN included) and
return `PCL_ERR_*`, leaving the oscillator unchanged; `process` trusts its arguments.

**Why a depth parameter.** CLAUDE.md fixes pitch modulation in octaves, but Q15 cannot hold a
modulation signal above +/-1. Scaling a normalized signal by `pitch_depth_oct` gives every
sample type the same range. Resolution at the Q15 extreme (8 octaves) is 0.29 cent per LSB; at a
depth of 1 octave 0.037 cent.

**Effective limits (behaviour, not errors).** After modulation the increment is clamped to
`0.45 * 2^32`. The pulse width is clamped to `[2*dt, 1 - 2*dt]` (`dt` = increment as a fraction
of a cycle) so the two edges' correction windows never overlap; above `sample_rate/4` that
collapses the pulse to 50 % (tested).

### New public types

* `pcl_hz_t`: frequency in Hz. Float builds `float`; fixed-point builds unsigned Q16.16
  (0.000015 Hz resolution, up to 65535 Hz), so frequency setters need no float on a no-FPU part.
  Constants: `PCL_HZ(x)`. The Hz-to-increment conversion is a 64-bit integer divide, done in the
  setter only (once per frequency change, never in `process`).
* `pcl_oct_t`: octaves. Float builds `float`; fixed-point builds signed Q4.28 (range [-8, 8)).
  Constants: `PCL_OCT(x)`.
* Helpers `pcl_mul_coef_q15` / `pcl_mul_coef_q31`: scale a non-negative coefficient by a
  modulation sample in the coefficient's own format. The Q15 one uses 32-bit arithmetic only
  and is tested bit-exact against a 64-bit reference.

## Algorithms

### Phase accumulator

`phase` is `uint32_t` in every build; wraparound is the intended behaviour. The wrap is the
carry out of the add. Frequency resolution is `sample_rate / 2^32` (about 0.00001 Hz at 48 kHz),
identical on all targets. The smoothed frequency is held as cycles/sample in `pcl_coef_t`
(Q2.30 in fixed-point builds); the 32-bit increment is that value shifted left by 2.

### Control rate: how pitch and PWM are applied

Every `PCL_CONTROL_DIV` samples the oscillator **ticks**: it advances the frequency and width
smoothers one step (their ramps are sized in ticks, so the glide still lasts ~5 ms), reads the
modulation inputs at that sample, computes the new target increment and pulse threshold, and
steps both linearly toward them over the next period. The tick counter lives in the struct and
counts from the start of the stream, so output does not depend on how the stream is cut into
blocks (tested for 1, 7 and 256).

* **Consequence 1 - bandwidth.** Modulation bandwidth is about `sample_rate / 32` (1.5 kHz at
  48 kHz): fine for vibrato, envelopes, LFO-PWM and keyboard CV, not audio-rate FM.
* **Consequence 2 - lag (found while verifying the sweep example).** A tick reads the
  modulation at the *start* of a period and the increment reaches it at the *end*, so
  modulation arrives one control period late (16 samples = 0.33 ms at 48 kHz). On a steady
  exponential sweep this appears as a constant relative frequency error of `-k * 0.33 ms`
  (-0.012 % on the 20 Hz to 20 kHz / 20 s sweep) and a phase error of `f(t) * 0.33 ms`
  (3.3 cycles predicted, 3.5 measured at 18 s, where f = 10 kHz). It is inaudible; it is
  not a bug, and removing it would need look-ahead, which block-size independence forbids.
* At each tick the previous period's target is snapped to exactly, so a static pitch has zero
  accumulated error.

### Pitch modulation: octaves to increment

`inc_eff = inc_base * 2^oct`, `oct = pitch_mod * pitch_depth_oct`. No `exp2f`, no float in
fixed-point builds:

1. Split `oct` into integer part `k` (-8..7) and fraction `f`.
2. `2^f` from a **256-segment table with linear interpolation**; `uint16_t` mantissas
   `(2^(i/256) - 1) * 2^16` (the last, 65536, saturates to 65535). The interpolation rounds.
3. `inc_eff = (inc_base * 2^f) << k` using 16x16 partial products, so it stays 32-bit-only on
   Cortex-M0+ (no `UMULL`).
4. Clamp to the 0.45 * 2^32 limit.

The float build uses the same table instead of `exp2f`, so the three builds behave alike.
Accuracy (measured): constant-modulation tests of +0.3, -2.1 and +3.25 octaves land within
0.05 cent (3e-5), as budgeted; a 20 s sweep agrees across float, Q15 and Q31 to 0.003 cycles.

### Band-limiting: PolyBLEP / PolyBLAMP

For an edge, let `e` = distance to the edge divided by the window (`0 <= e < 1`) and
`q = 1 - e`. The window is one sample's phase increment (`win` = the larger of the increment at
the start and end of the control period, so it covers the whole period).

* **Step of height J:** the sample before the edge gets `(J/2) * (+q^2)`, the sample after gets
  `(J/2) * (-q^2)`. This is the 2-point PolyBLEP residual.
* **Slope change of M per cycle:** both neighbouring samples get `M * dt/6 * q^3` (the integral
  of the step residual, i.e. the 2-point PolyBLAMP). Derived here rather than copied from the
  literature, since conventions differ; it is validated by the double-precision model test and by
  the measured aliasing improvement on the triangle.
* **Saw:** one edge per cycle, `J = -2`. **Pulse:** `J = +2` at phase 0 and `J = -2` at the width.
  **Triangle:** corners at phase 0 (`M = +8`) and 0.5 (`M = -8`), so the correction is
  `+/-(4/3) * dt * q^3`.
* **Sine:** quarter-wave table folded by symmetry, linear interpolation.

`e = d / win` needs a division, so the reciprocal of the window is cached and recomputed only
when the window changes (never for a static pitch; at most once per control period under
modulation). Fixed point keeps it as a normalized mantissa: Q15 uses a 16-bit reciprocal from
one 32-bit divide; Q31 uses a 32-bit reciprocal from one 64-bit divide (the costliest part of a
tick on M0+). An edge sample then costs multiplies only. The window is `max(inc at both
ends of the period)`, so `d < win` always holds; a fast pitch sweep makes `e` slightly off in
the period's middle. That error is bounded by the pitch change within one period and was not
separately quantified.

**Measured aliasing** (non-harmonic power relative to the fundamental, 4-term Blackman-Harris,
+/-6 bins excluded around each harmonic; identical in float, Q15 and Q31). A 2-point PolyBLEP is
a modest filter, not a transparent one:

| Waveform | f0 | Naive | Band-limited | Improvement |
|----------|----|------:|-------------:|------------:|
| Saw | 1234.5 Hz | -12.9 dB | -29.1 dB | 16.2 dB |
| Saw | 3217.3 Hz | -8.8 dB | -25.0 dB | 16.2 dB |
| Saw | 6011.1 Hz | -5.5 dB | -18.6 dB | 13.1 dB |
| Pulse (0.37) | 1234.5 Hz | -15.1 dB | -30.6 dB | 15.6 dB |
| Pulse (0.37) | 3217.3 Hz | -11.3 dB | -30.0 dB | 18.6 dB |
| Triangle | 1234.5 Hz | -46.8 dB | -59.9 dB | 13.1 dB |
| Triangle | 3217.3 Hz | -35.0 dB | -49.8 dB | 14.7 dB |
| Triangle | 6011.1 Hz | -26.3 dB | -40.6 dB | 14.3 dB |
| Sine | 1234.5 Hz | | -88.6 dB (float/Q31), -87.8 dB (Q15) | |
| Hard-synced saw (slave 2701.9 Hz, master 1000.7 Hz) | | +1.6 dB | -13.5 dB | 15.1 dB |

The first draft said "tens of dB better"; the measurement says 13-19 dB. Callers who need more
should oversample or wait for a higher-order variant. The test limits are the measured values
plus about 3 dB.

### PWM

Control-rate: the pulse threshold (Q0.31 fraction of a cycle) is
`clamp(pulse_width + pwm_depth * pwm_mod)` at each tick and interpolated per sample, so sweeps do
not zipper. Only `PULSE` reads `pwm_mod` (tested: saw output is bit-identical with and without it).

### Hard sync

The master publishes its phase wraps in `sync_out`; the slave consumes them as `sync_in`. Both
are `pcl_sample_t` buffers.

* `0` = no event. A non-zero `d` in (0, 1) = "the master wrapped `d` samples before this
  sample", `d = phase_after_wrap / increment`. A wrap that lands exactly on a sample instant is
  reported as 2^-15 (the smallest non-zero value in every build).
* The slave's phase at the event is `phase - d * inc`. The jump between the waveform there and the
  waveform at phase 0 sets the correction height, so it works for every waveform and every
  pair of frequencies (no jump when the slave is already at 0).
* The correction needs **no division**: the event is `d` samples before the current sample and
  `1 - d` samples after the previous one, so `e = d` and `e = 1 - d` directly.
* **Why one sample of latency:** the *previous* sample must be corrected too, and it was computed
  before the event was known. The oscillator therefore holds one finished sample back; a sync event
  corrects both the held sample and the current one. Without this the correction would be
  one-sided or would need to look ahead into the next block, which would break block-size
  independence.
* `sync_out` also reports a slave's forced restarts (so chains work). Request it consistently
  across calls; toggling it mid-stream can drop a wrap at the boundary.
* `sync_in` takes **any signal without undefined behaviour**. A sample that is not a fraction is clamped at the input: negative or NaN
  means no event, and a float above 1 counts as 1 (in fixed point the largest sample is already 1). Before this, a negative sample was
  signed overflow in the Q31 build and an out-of-range float-to-unsigned conversion in the float build (found by patching noise into
  a slave's sync input in the PulseRack rack, under UBSan).

**Known limitation:** if a slave would also wrap naturally within the same sample as a sync event,
that sample receives both corrections and glitches slightly. It is rare (probability about the
slave's `dt`) and was not quantified.

## Memory

### State (measured)

`sizeof(pcl_osc_t)`: **104 bytes (Q15), 112 bytes (float and Q31)**; no heap. (The first draft
estimated ~76 and under-counted the window, reciprocal, correction-scale and delay-line fields.)

### Constant tables (measured, flash)

| Table | Entries | Q15 build | Q31 / float build |
|-------|--------:|----------:|------------------:|
| Quarter-wave sine, 256 segments + guard | 257 | 514 B | 1028 B |
| `2^x` mantissa, 256 segments + guard | 257 | 514 B | 514 B |
| **Total `.rodata`** | | **1030 B** | **1544 B** |

Both tables are shared infrastructure (a future LFO will reuse the sine, `pcl_math.h` pitch
conversions the exp2), so they are paid for once library-wide. Quarter-wave sine accuracy from
linear interpolation is about 4.7e-6 (-107 dB). `tools/gen_tables.c` generates them;
`tests/test_tables.c` compares the checked-in tables against `libm` (so stale or corrupted data
fails a test); regenerate with `gen_tables > src/core/pcl_tables.c`. The checked-in file was
verified identical to the generator's output when this module was written.

### Code size (`pcl_osc.c`, text bytes, arm-none-eabi-gcc)

| Target | Build | `-O2` | `-Os` |
|--------|-------|------:|------:|
| Cortex-M0+ | Q15 | 3708 | 2500 |
| Cortex-M0+ | Q31 | 4636 | 3220 |
| Cortex-M4F | float | 3380 | 2640 |
| Cortex-M4F | Q31 | 3916 | 2724 |

Runtime dependencies of the M0+ Q15 object: integer helpers only (`__aeabi_idiv`, `lmul`, `uidiv`,
`uldivmod`) plus `memcpy`, which the compiler emits for the struct copy at the top of
`pcl_osc_process`. The soft-float check in the `cm0plus-*` presets passes.

## Rate

Phase accumulation, waveforms, band-limiting and sync: audio rate. Pitch and PWM: control rate with
per-sample linear interpolation.

## Cost (cycles per sample): MEASURED on a Cortex-M33

Measured on a **FRDM-MCXN947 (Cortex-M33 + FPU, 150 MHz)** with the core's DWT cycle counter,
`-O2`, running from flash with the SDK's default flash cache on, 48 kHz sample rate, 256-frame
blocks, oscillator only (`scripts/mcxn947_bench.py`, cases in `platform/bench/pcl_bench.c`).
Figures are the fastest of 8 blocks divided by 256; the spread between blocks is under 2 %.

| Case | Q15 | Q31 | float |
|------|----:|----:|------:|
| sine 1 kHz | 101 | 105 | 93 |
| triangle 1 kHz | 107 | 117 | 98 |
| saw 1 kHz | 112 | 118 | 82 |
| pulse 1 kHz | 142 | 149 | 92 |
| sine 5 kHz | 101 | 105 | 93 |
| triangle 5 kHz | 115 | 129 | 103 |
| saw 5 kHz | 116 | 122 | 84 |
| pulse 5 kHz | 149 | 157 | 97 |
| sine, pitch + PWM modulated | 108 | 116 | 99 |
| triangle, pitch + PWM modulated | 116 | 131 | 106 |
| saw, pitch + PWM modulated | 120 | 130 | 88 |
| pulse, pitch + PWM modulated | 151 | 162 | 99 |
| saw, hard-synced | 119 | 124 | 87 |
| triangle, hard-synced | 115 | 126 | 104 |

* **About 82-162 cycles per sample, nearly independent of the waveform.** At 150 MHz and 48 kHz
  (3125 cycles per sample) one voice costs about 2.5-5 % of the core, so roughly 20-40 voices
  before mixing and other work.
* **These figures were re-measured after the sine, saw/triangle and octave-scaling code moved into
  shared internal headers for the LFO** (output byte-identical in all three builds, verified against a
  saved copy of the previous output). The generated code changed: Q15 got 0-9 cycles faster, Q31
  1-7 slower and float 0-4 slower (at most about 5 %). The cause was not investigated; inlining and
  code layout are the likely reasons. The earlier figures (e.g. 110 / 104 / 93 for the 1 kHz sine)
  are superseded.
* **The pre-implementation estimates in the first draft (12-55 cycles) were 3-5x too
  optimistic** and have been removed. The waveform maths is a small part; the rest is the
  general per-sample path (saturating adds, band-limiting window checks, the one-sample delay
  line, phase/increment/threshold update), which is the same for every waveform. There is room to
  optimize it (a dedicated loop per waveform, fewer struct fields touched per sample).
* **Flash cache:** with the cache disabled Q15 costs 163-221 cycles per sample (measured before that change), so instruction
  fetch from flash is a meaningful part of the total. How much of the cached figure is still
  fetch stalls was not separated (that would need a run from zero-wait-state SRAM).
* **Not measured:** Cortex-M0+ (no hardware), so the M0+ and M4F figures in the first draft are
  withdrawn. The M33 numbers do not transfer to M0+, which has no 32x32->64 multiply and a
  slower core.

## Fixed-point behaviour

* Saw/pulse/triangle derive from the phase's top bits (the sign bit flipped is a two's-complement
  ramp); the triangle is `1 - 2|saw|`.
* Q15 corrections use Q0.15 fractions (`q`, `q^2`, `q^3` via `pcl_mul_q15`); Q31 uses Q0.31 via
  `pcl_mul_q31`. All additions saturate; the phase accumulator is the only wrapping arithmetic.
* Measured against the double-precision model of the same algorithm (static pitch, 1 kHz and
  7.3 kHz, all four waveforms): worst error **float 1.2e-4, Q15 7.6e-5 (about 2.5 LSB), Q31
  6.0e-5**. The float and Q31 figures are dominated by the model's own phase drift over 2048
  samples, not by the oscillator's precision. Test tolerances: 1.5e-4 sine, 5e-4 others.

## Tests

`tests/test_osc.c` (all three sample types), plus `test_tables.c`, and additions to
`test_types.c` for the new helpers and macros:

* init/setter validation (NULL, every range edge, NaN/Inf in float), state unchanged on error;
* latency and `set_phase`;
* agreement with a double-precision model of the algorithm (4 waveforms x 2 frequencies);
* frequency accuracy from sync-event timing (20 Hz .. 20 kHz) within 5e-6, with sub-sample jitter
  under 2e-3 sample; pitch modulation in octaves within 3e-5; glide lands on target;
* waveform shape: zero mean for saw/triangle/sine, pulse DC = `2*width - 1`, peak level;
* PWM (both directions, `NULL` equals zero modulation, saw unaffected); pulse clamp at high pitch;
* aliasing vs the naive waveform for saw/pulse/triangle at several pitches; sine purity;
* sync: `sync_out` timing and no effect on audio; slave follows master and beats the naive
  restart; a restart on every sample with random sub-sample positions stays bounded;
* `reset` determinism; **block-size independence** (1, 7, 256) with pitch mod, PWM, sync in and
  out, and a glide all active, for every waveform;
* extreme parameters (max frequency, depth 7.9, square modulation, sync storms, width limits):
  finite, bounded, no denormals in float.
* `sync_in` outside the contract (negative, NaN, infinity, above 1, the most negative sample): bit-identical to the sanitised input, in audio and
  in `sync_out`, for every waveform; clean under UBSan in all three builds.

Also run clean under GCC and Clang, at `-O0` and `-O2`, and under ASan + UBSan in all three
builds. Not verified: MSVC (`/W4 /WX`).

## On hardware

`scripts/mcxn947_bench.py` builds the library into a firmware for the FRDM-MCXN947, flashes it,
renders 14 deterministic oscillator cases on the chip, streams them back over the board's USB serial port and
compares them with the same cases rendered by the host build. Result on a Cortex-M33 (GCC 15,
`-O2`) against an x86-64 host (GCC 16):

* **Q15 and Q31: bit-exact** in all 14 cases; every case passes its CRC.
* **float: bit-exact too** (maximum difference 0.0 over 2 048 samples in every case), so the
  M33's FPU and the host agree to the last bit for this code.
* The measured core clock was 150.04 MHz (counted from UART timing, not assumed).

See the README for how to run it. The firmware is 17-18 KB of flash and 17-26 KB of RAM. The harness was
later extended with the noise and sample-and-hold cases (21 cases in total); the 14 oscillator cases and
their cycle counts were re-run afterwards and are unchanged (see [noise.md](noise.md)).
